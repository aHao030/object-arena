# 从用户角度循环质询的记录

版本：v0.3。工作始于2026-11-10，复核记录于2026-11-11。三轮仅评价设计文件，没有运行产品或假装进行真人访谈。

## 循环与停止条件

每轮执行：形成具体方案 → 站在使用者角度提出可导致误解/失败的问题 → 修改对应合同和验收 → 独立复核。若出现新的文档P0/P1则继续修订；已确认问题关闭、没有新发现的P0/P1、剩余假设有验证方法时，结束本次文件生成。

P0是安全、不可控支出、跨账号泄漏或结果可信度破坏；P1是核心流程不可完成、关键合同矛盾或跨端明显不公平；P2是文案精度与范围同步问题。这个停止条件不意味着不存在未发现的问题，更不意味着产品已经“完美”。

## 第1轮：先拆开容易混淆的构思

| 用户质询 | 修订结果 |
|---|---|
| 我的石头为什么可以自己跑？ | 标准驱动底座，公开质量、功率、电量、接触牵引；不直接改位置 |
| 只拍一面就知道钢杯多重吗？ | 单照片只生成外观推测；校准尺寸，实心估算与声明质量分路线 |
| 物体大一点为什么一定多花token？ | API原生用量、平台PC与竞技CP分开；体积进入CP |
| 我能用电脑直接操控吗？ | 真实用户选择实时操控；统一键盘与触屏输入 |
| 手机、平板和电脑能一起玩吗？ | 真实用户追加主流设备要求；浏览器入口、服务器裁判与设备分档 |

## 第2轮：三位独立审阅者质询

分别模拟普通/建模/BYOK用户、物理/联机开发者、移动端/验收者，合计提出20条意见，部分主题重叠。下表按问题合并，均已实际修订主文件。

| 质询与风险 | 修订位置与结果 |
|---|---|
| 估计价勾选后到底能不能生成？ | COST、MODEL、C02统一hard/estimate/unknown；estimate逐任务接受风险，不称硬上限 |
| 连点或换个请求键会重复消费报价吗？ | DATA、API、C03明确quote原子绑定一个operation、最多一次收费提交 |
| 好友拿什么进我的房间？ | API新增一次性邀请和第二玩家join，锁席、检查build并签发本人凭证 |
| 私有物体怎么给对手看，又不泄露原照片？ | API和S09限定本局必要派生资源授权，原件仍私有 |
| 空心杯子为什么被强迫按体积算质量？ | P03/P04与主规则分质量路径；V_solid可为null |
| 还没生成，怎么先给我看碰撞代理？ | spec、MODEL、A02分生成前初估和生成后精确确认，不保证收费产物能参赛 |
| 生成中删除照片，结果会重新出现吗？ | DATA、S08加入删除墓碑，迟到产物隔离清理，费用独立对账 |
| 图片里有杯子和手，究竟生成哪个？ | MODEL、A02加入人工裁剪、主体与实际发送图片确认，改图使报价失效 |
| GLB动画姿态会和碰撞体不同吗？ | API、S10首发只支持静态烘焙网格，多静态节点合并固定载荷 |
| 朝向改变后CP和重心还用旧值吗？ | 统一朝向在资产发布前烘焙，固定对中装配，Build不提供自由变换 |
| 我出界时对方刚好失联，谁赢？ | PHYS与M08公开每tick合并lose事件的总顺序及最后完整物理步 |
| 输入只是收到，客户端就可以丢掉吗？ | ARCH、API、R07采用lastAppliedSeq/appliedAtTick确认实际应用 |
| 手机摇杆的斜角是否比键盘弱？ | DEVICE、API、M03统一独立油门/转向，两端均可满幅(1,1)，共用总功率上限 |
| 同一数值模型换单位为何应一样大？ | P01改成同一实物的三份等价编码样例，不再使用错误测试前提 |
| 不知道实心体积就一定不能玩？ | P04允许可靠代理＋声明质量；拒绝的是无可靠代理或不满足规则 |
| 重新仿真不逐位相同，普通回放也算失败吗？ | R01区分权威位姿回放和审计重演，不混淆发布门槛 |
| 只测一台手机20分钟就算全部支持？ | DEVICE与R05统一所有目标机型20分钟与可追踪真机矩阵 |

## 第3轮：对修订后的真实文件复核

- 普通/建模/BYOK审阅者确认其7项关闭，未发现残留P0/P1；另指出未知计费的“测试连接”用语含糊，已改为仅允许确认免费的元数据查询。
- 技术审阅者确认其8项关闭，未发现新增或残留P0/P1。
- 设备/验收审阅者确认其5项关闭，250ms输入超时、2s心跳、每局累计15s失联、无预测客户端准入规则已对齐，未发现新增或残留P0/P1。

复核结果限定于本次阅读的规格一致性；没有把未完成的性能、物理标定或真人手感测试算成已通过。对应后续门槛见 [验收](ACCEPTANCE.md) 和 [开放问题](OPEN-QUESTIONS.md)。

最终静态核验：38份Markdown文件可读取；23个本地文档链接全部有效；12个任务的依赖均存在且没有循环；CP示例重算为86。此核验不运行物理引擎、模型API或浏览器产品，也不代表功能测试通过。

## 下一次循环的输入

优先以两个真实设备完成实时推台原型，从实际手感和失效数据提问。用户若希望移除底座、增加攻击或加入机械结构，应从驱动力来源和物理边界重新展开决策，而不是只更换外观描述。
