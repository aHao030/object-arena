# 未决问题与可调整假设

没有把“完美”当成可证实状态。当前完成的是设计闭环；以下问题需要原型、真人或部署环境证据。

| 问题 | 当前默认/已知事实 | 如何消除不确定性 | 阻断什么 |
|---|---|---|---|
| 推台与底座是否符合用户心中的对战？ | 用户确认实时操控，未指定攻击机制；首发推荐推台 | 展示两端可玩原型，收集用户和首批玩家反馈 | 大规模实现/宣传定位 |
| 哪些主流设备能流畅参与？ | 目标电脑、Android、iPhone/iPad；尚未测试 | 真机矩阵、20分钟温控、上下文恢复 | 正式支持名单 |
| 触屏与键盘是否公平？ | 同一归一化指令与视野 | 小样本手感测试后扩大对局统计，必要时偏好匹配 | 排位 |
| 客户端无 WASM 预测能否玩？ | 首发比赛默认要求锁定解码/预测构建通过自检 | 关闭预测的弱网试验；未通过只保留非比赛页面 | 无预测设备准入 |
| 任意物体碰撞代理是否足够准确？ | 限定形状复杂度，展示差异 | 样本集误差与接触测试，失败则拒绝/简化 | 对应资产参赛 |
| 哪个模型 API 是首个真实接入？ | 用户尚未指定；协议适配器必须可替换 | 使用用户后续选择的服务文档、测试密钥和小额报价 | 真实 BYOK 集成，不阻断模拟服务开发 |
| 成本与 PC 定价是多少？ | 没有供应商实测或平台算力账单 | 测量端到端资源、失败率、对账，确认费用政策 | 对外收费 |
| 确定性构建怎么锁定？ | Rapier 官方资料表述有冲突 | 安装实际发行物并核对源码/哈希，对照快照 | 输入重放保证；不阻断权威位姿回放 |
| CP 公式是否平衡？ | r0.1 是可解释的初始公式 | 多体型、多材质、多动力组合真实对局 | 排位/最终参数 |
| 实际并发与地区延迟？ | 先单区域、1v1私密房间 | 固定实例压测、两地网络测量 | 并发与网络 SLA |
| 全球访问与模型服务限制？ | 不声称跨地域供应商均可用 | 确定部署地区、供应商授权/可用性和账单主体 | 正式发布地区 |

主观玩法选择可以由用户随时改变，不需要先为所有假设签字。下一步最有价值的证据是“手机和电脑实时玩完一局”，而不是继续增加设想。
