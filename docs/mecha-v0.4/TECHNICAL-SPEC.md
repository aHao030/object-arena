# 机体平台技术合同草案

用户指定的MuJoCo用于后台机械验证与选配浏览器工作台，详见[接入设计](MUJOCO-PLAN.md)。报告和竞技参数分开，同场比赛始终只有一个权威物理后端，不把离线测试当另一引擎赛场的等价证明。

本轮是设计修订，不是已实现服务。以下替代旧底座、旧CP公式及油门/刹车对战合同；凭证隔离、费用幂等与私有资产原则继续保留。

## 技术主线与复用边界

沿用TypeScript、Three.js、Rapier和Colyseus作为优先原型路线，新增骨架/刚性分件编辑、机体装配图与战斗房间；不将旧Canvas演示直接升级为正式仿真。采用动态根体和有上限的地面驱动力、推进力、姿态控制；不把Rapier运动学角色控制器称为自然受力系统。

首发姿态辅助按战斗规则的1,200N·m/400W机械功上限，在基础控制0.5kW内运行；地面须有接触，空中须有可运行推进模块。失衡状态和动作切换须在原型校准后冻结，不能暗中锁住姿态后宣称真实双足机器人。骨架动画、IK与装甲形变只控制显示，命中位置来自服务器规范动作与代理。

图像生成、分件、绑定和清洗在后台工作进程执行；模型建议不进入实时判定。数据库持久化业务与账本，对象存储保存私有原件、派生产物和回放；重建或骨架服务故障不阻断已有合格机体比赛。

Babylon.js/Havok与Godot保留为技术对照选项，是否更换须由同一场景原型的手机帧耗时、网络校正与资产工作量决定；没有因为新题材就无证据更换全部引擎。详见研究证据。

## 数据实体与不可变引用

| 实体 | 内容和不变量 |
|---|---|
| SourceAsset | 私有照片/网格、用户来源声明、扫描单位、校准尺寸；不是战斗参数 |
| MachineDraft | 可编辑分件映射、关节确认、配色、插槽配置、revision；改变输入使旧报价与确认失效 |
| PartAssetVersion | 不可变视觉网格/LOD、rigid绑定、来源/权利元数据、适配报告、内容哈希 |
| FrameTemplateVersion | 标准身体段、关节范围、插槽兼容、动作曲线、根体/命中代理、参考尺度、扶正控制版本 |
| ModuleProfileVersion | 武器/装甲/推进器功能、质量、功率占用、能耗、热量、CP、包络、失能规则 |
| MachineBuildVersion | 不可变frame、part、module版本及变换图，代理报告，总质量、CP、控制配置、ruleset引用 |
| Ruleset | 不可变运动/伤害/热量/供能/锁定/网络参数、地图/引擎/动作/协议哈希 |
| GenerationOperation / CostQuote / LedgerEntry | 操作幂等、一次报价一次收费提交、平台预留与结算、第三方费用约束等级、尝试记录 |
| Match / ReplayEvidence | 两个冻结装配清单，实际应用输入tick、弹丸/命中/能量/部位事件、权威位姿帧、唯一终局 |
| MechanicalTestReport | 工作台报告：装配/模型/引擎/控制器/测试哈希、条件、轨迹、诊断；不直接授权竞技能力 |

装配图禁止循环、重复占槽或同一模块实例多次产生能力；展示网格中同样的两个枪管不会绕过一个模块实例的射速。原件删除不改写进行中对局，生成中的删除使用tombstone防止迟到回写。

## 初始模块目录必须完整

以下只是m0.1数据样例，正式发布需校准并冻结，不能作为真实硬件性能。

| 条目 | 质量kg | CP | 主要功能 |
|---|---:|---:|---|
| 人形基础机架 | 100 | 20 | 根体、电机、有限稳定辅助、50kJ容量、3kW科幻反应堆；基础控制0.5kW含辅助功耗 |
| 轻装甲 | 20 | 10 | 不减免规则伤害 |
| 标准装甲 | 30 | 20 | 对穿过屏障后命中身体的规则伤害乘0.85；不增加屏障值 |
| 脉冲步枪 | 10 | 20 | 500J/发，充能0.1秒占5kW，充能完成才生成弹丸 |
| 机架内置近战刃 | 4 | 10 | 900J/次，充能0.15秒占6kW；动作轨迹按规则，不允许复制 |
| 护盾 | 12 | 10 | 激活时占1kW、300屏障值 |
| 标准推进背包 | 24 | 15 | 3,000N，12kW，占用背部槽 |
| 高推力背包 | 34 | 25 | 3,600N，14kW，占用同一背部槽；替换标准背包 |

标准装配180kg/95CP；轻装甲＋高推力背包同为180kg/95CP。CP之外仍需检查所有硬上限。推进激活时替代地面驱动，不叠加两套主动推进；反应堆充电功率不作为额外输出能力。

20kW是同时运行的总线输出上限，不是所有铭牌之和。每tick先保留待机和已承诺且仍合法的持续充能，再分配地面或喷射驱动、护盾维持/开启，最后按输入事件序号接受新武器动作；右臂步枪/刃互斥。既有充能不被新推进抢占，较低优先级动作无法分配时当tick不生效并提示；护盾维持因不足停用时不得仍挡弹。

高推力＋护盾＋近战充能需要21.5kW，拒绝新近战；若步枪5kW已在充能，开启14kW喷射后连待机占19.5kW，护盾1kW请求被拒绝。超功率时绝不遗忘上tick尚在充能的负载。充能完成、取消或对应模块失能后才释放占用。

武器动作开始预留本次能量，在充能区间按已占功率消耗；结束不再重复扣一遍。中途取消/失能退回未消耗预留，已消耗不退；开火冷却与attackId不能因取消被提前刷新。反应堆只在规则允许时给空闲容量充能，不能把预留中的能量重复使用。

## 几何、资源和可见性

源文件上限暂为照片10MB、GLB/STL50MB。所有解析隔离运行，拒绝外部URI、脚本、动画事件、未知扩展和畸形数值；生成输出走相同清洗。骨架只读白名单变换与蒙皮数据，用户自带碰撞节点不直接成为服务器代理。

参考上限：一个机体最多16个受控命中代理、32个可动骨段、每人同时16枚弹丸；同时只载入双方比赛LOD与必要资源。省电档每机体30k三角面、总场景120k，首局下载目标≤20MB，显示目标30fps；标准档60fps。均须测内存峰值、解码、持续20分钟和网络，不把限额当作已达帧率。

标准框架与受击主体必须可见且不透明，不能通过透明贴图或删除躯干网格变成看不见的命中盒。自定义部件须在slot envelope内，并覆盖/对应模板主体；不能过大遮挡视野、投射假的盾或严重小于受击体。超差时显示模板实体结构或要求修正，不直接参赛。

对手机体、掩体、弹丸和功能状态采用相同的有效信息范围；省电档可用轮廓/低LOD代替，不能降低敌人可见距离或删去可命中目标。宽屏与竖屏要保留同一有效战场信息；不同输入方式的锁定策略由规则定义。

## 输入、瞄准与网络

目标服务器物理60Hz、输入30Hz、快照20Hz，待压测确定。客户端输入为`{seq,moveX,moveZ,aimYaw,aimPitch,fire,melee,boost,lift,shield,lockRequestId?}`；move二维长度≤1，按钮严格布尔。fire为持键自动请求、只在合法冷却完成且通道空闲时启动一发；melee只在服务器观察到false→true边沿时请求，重复true不连续挥刃。同一seq既有melee边沿又fire为真时，近战优先，步枪不排队到之后补发；通道忙时近战请求丢弃并反馈，需松开再按。boost/lift/shield为持续状态，超时或失焦归false。服务端为每次真正开始的攻击生成唯一attackId，不把渲染帧当攻击次数。

推进向量按战斗规则与lift合成，不受瞄准俯仰暗中改变；手机“升空”键同时置boost/lift，普通喷射键仅置boost，两端同义。瞄准合法且受转向速率限制，不接受位姿、伤害、命中或自由枪口位置。

电脑WASD＋鼠标瞄准、射击/近战/喷射/护盾。手机左拇指移动，右侧提供“按住开火并拖动瞄准”的射击触区，保证恰好两指也可持续移动、瞄准、射击；另有仅拖视角区和明确动作键。pointer capture保持原触点归属，cancel/失焦/后台释放持续开火，不把手指滑出按钮变成卡键。其他动作允许顺序操作，首发不要求两指同时完成所有五种动作。

目标锁定为两端共享显式机制：25m内、相对机体前向的60°半角锥且无遮挡才接纳，超范围/遮挡持续0.2秒断锁，目标失能/结束即时断锁；辅助跟随受同一180°/s转向上限，不自动开火、穿墙或增加命中率。以上为待手感验证的初始参数；不能只在手机暗开自动命中/冷却。

服务端按有效输入顺序和实际应用tick执行；快照含serverTick、lastAppliedSeq/appliedAtTick、根体/规范动作状态、能量热量、模块失能、弹丸事件和matchState。未应用输入不能提前ACK，重连返回序号基线并清空过期队列。客户端本地预测、远端插值，胜负仍按服务器。

原型优先服务器弹丸与无回溯命中。若日后采用光束/瞬时射线，另立有界历史命中方案，验证历史掩体/部位/开火时间、可追溯视图与回溯窗口；不能仅装框架就宣称已实现机甲lag compensation。

同一步按战斗规则处理连续热量、充能完成与过热后，收集合法攻击并推进命中，再提交部位变化与lose事件；本步双方同时被击毁可双输。前一tick已失能模块不能产生新攻击；已生成弹丸到碰撞/寿命终止。固定精度、盾溢出、折扣与传伤顺序完全采用战斗规则，不另建一套客户端算法。

## HTTP合同增量

| 操作 | 外部行为 |
|---|---|
| POST /v2/machine-drafts | 选择sourceAsset、whole-body或core-shell适配路线与frameTemplateId；返回revision与缺失项 |
| PATCH /v2/machine-drafts/{id}/mapping | 带If-Match确认分件/关节/插槽候选，产生新revision，不信任客户端参数 |
| POST /v2/machine-drafts/{id}/preview-check | 跑固定动作和代理/资源检查，返回可解释报告；不等同发布 |
| POST /v2/machine-drafts/{id}/publish | 需revision、确认报告、允许模块目录与规则；返回不可变MachineBuildVersion |
| GET /v2/catalog | 返回frame/module/ruleset完整版本、能力、上限与目录哈希 |
| POST /v2/quotes 与 /v2/generations | 指明vision/image-to-3d/part-segmentation/rig-suggestion能力，绑定输入摘要与revision |
| POST /v2/matches | 带本人build、规则和模式创建私密/训练房；返回短期本人joinToken |
| POST /v2/matches/{id}/invites 与 /join | 一次性邀请、第二玩家提交本人build，原子锁席并验证相同规则 |
| GET /v2/matches/{id}/replay | 只授予被授权用户读取必要比赛派生包和证据，不包含对手原图/凭证 |

认证、ownerId、修订冲突、幂等键、限流与短期签名覆盖全部路径。v1旧推台接口不能静默解释成机甲协议；旧原型明确保留其版本。

## 自带API、费用与数据安全

通用vision API不等于image-to-3d，更不等于能分件或绑定。每个适配器分别probe能力、输入限制、任务/取消/幂等与计费语义。可以用不同服务分别做外观、分件和绑定；首发不用任何研究模型作为不可替代前提。

每一步显示实际发给供应商的文件、猜测/产物边界和失败权益。quote绑定输入摘要、revision、阶段、质量、价格版本；一个quote原子绑定一个operation，最多一次收费提交。workflowId绑定所有阶段及所有者，分别保存platformPcCap与按供应商/币种分组的费用授权；没有明确汇率与授权不跨币种合并成一个虚假准确余额。

平台PC与第三方hard都以“已结算＋未决/已预留＋新请求上限≤对应总上限”在同一事务检查和预留；总100时并发两个60只能启动一个。未知结果保留预留、阻止依赖它的下一次收费，查询对账后才能释放。estimate仅是累计估价与明确风险接受，不对第三方承诺总硬上限；若用户要求第三方严格总上限，该工作流只允许hard适配器。逐步估价不能被包装成有可靠总封顶的整单。增加授权须用户再次明确发起，不自动扩额。

hard显示第三方可靠上限；estimate必须逐任务接受估价可能超出且不能称硬上限；unknown禁止收费请求，只允许已确认免费元数据查询。平台PC可严格限制，上游超时可能已经收费；unknown状态先查询对账、不盲目重买。平台PC释放不承诺第三方退款。

密钥后端加密、只存secretRef；默认仅审核供应商HTTPS域，调用/轮询/产物下载逐次检查DNS与地址，防私网/重绑定/跨域泄露。文件私有，不把raw mesh暴露给对手；分享或比赛授权只含必要LOD/代理/档案白名单。删除tombstone拦截迟到结果，显示备份/比赛证据例外，沿用原件7天、闲置草稿30天、必要证据30天的拟议保留窗口，正式发布前实测兑现。

## 结算和回放

机体清单、地图、规范动作、引擎构建和协议共同冻结。记录实际输入、弹丸/命中/资源事件、20Hz权威位姿帧和关键哈希。观看回放用权威帧；输入审计重演不保证跨引擎构建逐位相同。

结果以matchId唯一且事务持久化；终局前服务器崩溃、无法证明结果则无效局，不由客户端填胜负；已提交终局幂等恢复。客户端后台和图形故障不暂停对手，按累计失联规则处理。排位、奖品、交易和支付不在首发范围。
