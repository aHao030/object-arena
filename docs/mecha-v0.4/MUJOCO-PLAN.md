# MuJoCo如何用于本项目

2026-11-11用户指定[google-deepmind/mujoco](https://github.com/google-deepmind/mujoco)。结论：有直接价值，纳入机体机械验证方案；尚未安装、集成或运行。

## 能力与接入位置

MuJoCo针对多关节、接触与控制仿真，适合研究关节轴/范围、质量惯量、电机力矩、重装模块、碰撞和稳定控制。当前已有官方JavaScript/TypeScript/WASM及浏览器Studio；单线程可作为广泛浏览器路线，多线程需要额外条件。绑定仍有WIP和平台测试注意项，不能据此宣称本平台所有手机已通过。[官方WASM说明](https://github.com/google-deepmind/mujoco/blob/main/wasm/README.md)

先接后台“机械验证工作台”：已确认机架/模块→受控MJCF/MjSpec模型→有界测试→轨迹和诊断。GLB/照片提供外观与确认的分件，不自动提供关节、电机或稳定步态。输入机械结构来自版本化模板，不运行用户任意XML插件、外链include或脚本，继续隔离与限额。

| 测试 | 回答的问题 | 结果边界 |
|---|---|---|
| 结构/关节扫描 | 轴、范围、惯量、连接是否有效 | 不恢复照片里不可见的真实机械 |
| 固定动作运动学检查 | 瞄准、抬臂、挥刃有无明显限位/干涉 | 通过不代表电机真的做得到 |
| 有限电机动态跟踪 | 给定负载下扭矩饱和与动作误差 | 不代表任意动作已学会 |
| 已有步态控制器对照 | 改装是否使指定控制器失稳 | 不证明所有地形/机体可稳定行走 |

MechanicalTestReport绑定build/frame/module、生成模型、MuJoCo发行物、控制器与测试哈希，保存步长、条件、轨迹和失败原因；改装后旧报告失效。界面显示“此机械测试通过/未通过/不适用”，不声称工程认证。

区分两种测试profile：game-proxy只验证现有根体/质量/推进数据，不声称检查了真实双足；articulated-lab须额外提供每段惯量、真实关节、有限执行器和控制器，才运行多关节动态测试。来源照片或当前根体参数不会自动补齐这些数据，缺失时报告“不适用/需补充”，不能生成假的全关节通过。

## 与实时竞技的边界

首发休闲竞技保持单一权威物理后端与冻结动作规则。MuJoCo工作台为机架研发和制作诊断，不直接改变CP、HP、武器伤害或比赛状态；辅助测试失败不自动否决符合休闲规则的外观装配。两个引擎同样的参数也不保证行为相同，报告不是跨引擎等价证明。

未来若采用MuJoCo承担全关节比赛，为新规则房间选择它作为唯一权威物理，所有玩家同版本、步长与控制器；重新验收命中、网络预测/校正、性能、回放与平衡。不能让同场玩家各选Rapier或MuJoCo分别裁决。

浏览器试验室可用单线程WASM，也可由后台计算、网页展示报告/轨迹；加载失败不阻断普通休闲对战。官方WebViewer的浏览器显示能力不等于本项目1v1竞技网络已完成。

MuJoCo Live是在浏览器本地计算的WASM应用；Python WebViewer在后台计算、浏览器显示且默认一个控制者和多个观看者。这两者是不同部署方式，都需要平台自己的竞技输入、权限和结算协议。

## 最小验证任务

先用原创简化机械臂/人形模板，比较轻重模块的关节力矩和跟踪误差，再让一个确认的用户装配导出受限模型；展示运动学通过但电机动力不足的反例。任务限时隔离，报告错误指回模块ID。

如评估替换战斗后端，再用两机体同场景测服务器步进、内存、网络校正和手机显示，用数据决定。源码Apache-2.0，文档素材和示例模型分别核对许可。详见[专项研究](../../research/mujoco-mecha-evidence.md)。
