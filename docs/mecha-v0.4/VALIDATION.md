# 可驾驶机体的验收与研发门槛

本清单全部待实现、待执行。调研和文档复核不能标记功能完成。

## 分阶段闭环

| 门槛 | 演示 | 不能用什么替代 |
|---|---|---|
| G1 驾驶可玩 | 原创预置机体在手机/电脑完成移动、瞄准、射击、近战、喷射、资源耗尽与试射 | 旋转模型、自动播放战斗、旧底座推台 |
| G2 自有模型可驾驶 | 用户分件GLB完成映射/动作预览/装配；另一个普通模型经明确同意作为核心外壳完成试驾 | 只在展示柜看到上传模型，战斗中偷偷换回预置皮肤 |
| G3 跨端对战闭环 | 两位玩家用各自的装配完成服务器1v1、相同结算、可解释回放、再改装 | 玩家房主合作演示、只上传未参战、两端各算各的胜负 |
| G4 照片接入同一闭环 | 自己API的有界照片生成、分件/核心路线、用户确认→复用G2/G3 | 生成一个漂亮静态mesh就称已完成驾驶 |
| G5 可发布休闲测试 | 预算、安全、真机、弱网与异常恢复通过，范围和支持名单明确 | 文档“无P1”或只有桌面截图 |

公开宣传“支持自己的照片和模型驾驶对战”需要G2–G4都通过；G1完成只允许称驾驶原型。未通过的输入形态明确标为制作草稿或实验功能，不隐藏后续修复工作量。

## 有代表性的行为测试

| 编号 | 场景 | 可观察通过条件 |
|---|---|---|
| A01 | 分件GLB与已有骨架GLB | 映射、前后左右、关节和固定动作一致；原始动画事件不能执行 |
| A02 | 整体STL或合并整机 | 不假装已经可动；明确缺失分件/方向，给人工修正或经同意的核心路线 |
| A03 | 单张照片和补拍 | 标明背面推测，生成前看实际发送图和阶段预算；不合格停在草稿，保留合规输出 |
| A04 | 错骨、反轴、缺腿、装甲穿插 | 动作检查报告指出问题；未经确认不发布，修改输入使旧确认失效 |
| A05 | 无分件服务的杯子STL核心装配 | 主动接受core-shell，确认躯干/缩放/裁剪，杯子刚性随躯干、标准头与四肢可见；无需源资产手脚分件即可发布、射靶、进私密局；whole-body失败不静默切换 |
| B01 | 模块重复、循环图、非法槽位 | 服务端拒绝；视觉双炮不获得两倍射速；旧请求不能改冻结版本 |
| B02 | 标准装配与高推力/轻装组合 | 目录重算分别180kg/95CP；高推力加标准装甲105CP拒绝，提示可换轻装 |
| B03 | CP内但功率并发不足 | 高推力＋护盾＋近战按目录21.5kW拒绝新近战，能量不负数，UI给原因 |
| B04 | 内缩代理、透明身体、超长枪/翼 | 预览揭示差异，未经修正不参赛；高低LOD的权威代理完全相同 |
| C01 | 有/无地面接触与推进 | 悬空时地面驱动无效，无喷射时按重力下降；同推力的重机加速更慢 |
| C02 | 无能量、过热、充能中取消 | 不能输出免费动力/伤害；未消耗预留返还且已消耗不退；冷却不被取消刷新 |
| C03 | 枪口贴墙、镜头见敌枪口被挡 | 弹丸不穿墙生成；扫掠命中不因低帧或高发送率漏检 |
| C04 | 一发穿过重叠部位代理 | 仅首个有效部位结算一次，固定同距优先序；回放可解释 |
| C05 | 近战同attackId多帧接触 | 同目标最多一次伤害，轨迹来自服务器动作，长刀外观不扩攻击范围 |
| C06 | 手臂/腿/背包失能 | 对应模块/移动能力按规则停用，已发射弹丸不凭空消失，无永久损坏源文件 |
| C07 | 双方同tick击毁、失联与命中混合、最终tick命中 | 按同一事件顺序得到唯一结算或平局，无客户端时间改写 |
| C08 | 盾剩20，同tick两次35，头部与已失能腿再被击中 | 两次屏障后余伤分别15/35，按装甲再部位/核心传伤与固定精度取整；头归核心，失能部位仍可见且按同规则传伤 |
| C09 | 先步枪5kW充能，再开启14kW背包和1kW护盾 | 待机/已承诺充能后先准入推进，护盾不足被拒绝，当tick不挡弹；负载不超20kW，充能不会被漏算 |
| C10 | 12m/s顺向喷射、扶正和失去背包 | 标准推力因9.6kW正机械功上限降低至800N；扶正正功≤400W且在基础控制能耗内，空中无背包不免费扶正 |
| C11 | 同一move/boost/lift输入在两端重演 | 推进方向一致，斜向不各轴获得满推力，aimPitch不改变方向，lift不单独提供动力 |
| C12 | H=95完成步枪，以及持续喷射先加到100时充能完成 | 前者发弹后过热、后者取消未提交攻击；退款只退未消耗，冷却不刷新，散热最后结算 |
| C13 | 同seq开火与近战同时为真、持续true和通道忙 | 有近战上升沿时近战优先、步枪不积压补发；持续melee真不重挥，fire按合法冷却逐发，忙时近战丢弃并提示 |
| N01 | 伪造位姿/伤害/目标ID/快速瞄准 | 非法输入被拒绝，目标锁定检查视野/遮挡/距离，不能客户端自己确认命中 |
| N02 | 未应用输入即发快照 | lastAppliedSeq不提前ACK，重连不重发积压开火，不重复attackId |
| N03 | RTT100ms/抖动20ms/丢包1% | 初始标准网络目标下50局无结算分歧，记录操作/校正延迟，原型后冻结可玩阈值 |
| N04 | RTT150–200ms、后台、图形丢失、反复掉线 | 明显网络风险提示，250ms归零，累计15秒不刷新，无永久开火或无敌 |
| N05 | 进程终局前/后崩溃 | 未决无法裁定则无效局，已落库终局幂等恢复一次 |
| D01 | 恰好2个touch pointer持续移动、拖瞄准并开火 | 左移右射击触区可完成三动作，无需第三指；其他动作可顺序执行。capture/cancel/失焦不丢触点、不卷页、停止持续开火 |
| D02 | 高低画质、横竖屏、两种输入 | 相同有效敌人信息、代理与锁定规则；低档用轮廓而非隐藏目标 |
| D03 | 目标设备真机矩阵 | Windows集显/Mac/Linux、两档Android、存量/当前iPhone及iPad，各连续20分钟；记录版本、帧耗时分布、内存与热降频 |
| P01 | 图像理解接口冒充3D/分件能力 | probe明确拒绝缺失能力，无假成功；预置和导入路线仍可用 |
| P02 | 跨阶段多次报价、重复/未知响应 | 工作流总额包含已花和已预留，一quote一收费提交；unknown先对账不盲重试 |
| P03 | 删除中迟到产物、越权与密钥 | tombstone阻止复活；对手只得必要派生包，日志/错误无密钥，SSRF链路被拦 |

## 仍需决策的原型证据

有限扶正控制的体验与数值、近战视觉代理误差、归一化机体对原模型身份的保留、锁定视野锥/断锁条件、武器与护盾优先序的易理解程度、模块平衡、照片分件成功率、供应商实际费用与数据政策。每项要有样例、测量与结论，不能靠模拟角色赞同关闭。

排位不在首发门槛内；准备开放排位时还需足够跨输入对局、CP组合平衡、延迟匹配和反作弊证据。正式支持设备只能列实测通过组合。
