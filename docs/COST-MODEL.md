# 费用、token 与参赛预算

这里的系数是产品设计示例，不是市场价格或供应商报价。

## 三种数值分别回答三个问题

| 数值 | 回答的问题 | 是否影响胜负 |
|---|---|---|
| 供应商原生用量 | 我的模型 API 花了多少？ | 否 |
| 处理额度 PC | 平台清洗、重建、存储等服务花了多少？ | 否 |
| 竞技预算 CP | 我的物体能参加哪个规则的比赛？ | 限制参赛组合，不能购买上限 |

模型可能按输入/输出 token、图片、任务、GPU 时间收费。没有 token 的图像转 3D 服务不虚构 token 数。上传大体积物体的照片未必比小物体耗更多 token；图像尺寸、生成分辨率和模型服务才直接影响模型成本。

## 体积的合理位置

在 CP 中保留体积约束，以避免超大物体挤占整个场地；质量、功率、电量一起纳入：

`CP = 20 × (总质量 / 10 kg) + 20 × (V_env / 0.1 m³) + 30 × (额定功率 / 200 W) + 30 × (初始电量 / 12000 J)`。

总质量包含 5 kg 标准底座。V_env 是固定装配坐标系里的载荷包围盒，不是材质的实心体积。相同 CP 仍需满足所有物理硬上限。服务器使用未四舍五入的值检查 CP≤100；界面保留两位小数并提示临界超额。

例：5 kg 载荷 + 5 kg 底座，0.5×0.3×0.2 m 的外包络、200 W、12,000 J：CP=20+6+30+30=86。若三轴同时放大两倍，包络体积变为八倍；均匀实心且同材质的质量也变为八倍，必须重新确认质量并检查上限，不能只调大视觉外观。

这套公式不是最终平衡结论；原型要对“小而重”“大而空”“低功率大电池”等组合做对局验证。不得通过提高 PC 消费绕过 CP。

## 平台处理如何报价

报价维度：重建模型档位/输出分辨率、输入数、处理后的三角面数量、纹理像素、凸分解复杂度、CPU/GPU 时间预算和存储时长。物理空间体积只有在改变体素分辨率/网格规模时才间接影响处理成本。

试行资源策略：先本地/受限预检，再给固定上限报价；处理进程有时间、内存和输出大小上限。超过上限暂停并请求一次新的用户发起任务，不悄悄切更贵的模型或提高费用。

平台账本流程：quote → reserve → run → settle(actual≤reserved) / release。平台重试使用同一 operationId 与幂等键，不重复预留/结算；输出交付前校验成功，平台失败按政策释放未结算额度。保留每次供应商调用的独立证据，不能以最终任务成功掩盖先前已收费尝试。

首发没有充值与支付实现；PC 可作为测试配额。生产计价需要真实供应商、实测算力成本与账单政策验证。

## BYOK 的上限到底保证什么

平台额度上限可以严格保证。第三方支出上限只有在供应商提供可验证的单价、最大用量和明确的扣费规则时才可约束；UI 必须分列两者。

- 有硬上限能力：发送 max tokens/分辨率/任务额度并校验报价，超预算不提交。
- 只有估计价：明确“估计，第三方可能超出”；用户须为这个任务显式接受风险，或改用可约束的供应商。
- 未知计费：阻止收费提交，仅允许已确认免费的元数据查询；不能用“测试连接”为名发送可能收费的推理请求，不得展示伪造的准确价格。

取消请求或 API 超时不代表供应商停止运行。平台 PC 可释放，但供应商已经发生的费用只能由供应商退款；不自动承诺退第三方费用。没有上游幂等能力的收费请求结果未知时先查询对账，不盲重试。
