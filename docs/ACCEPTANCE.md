# 开发验收与发布门槛

日期：2026-11-10。状态：验收设计，以下项目全部待实现和执行。文档审阅完成不等于功能验收通过。

本清单验证用户可观察的行为和外部契约；不通过给内部函数写同构测试宣称产品可用。主验证路径是“一位手机用户和一位电脑用户，各自准备物体，实时完成同一场权威物理比赛，并获得一致结算”。外部模型 API 使用可控模拟服务验证故障，另对最终选定供应商做小额、显式预算的集成验收。

## 核心用户闭环

| 编号 | 场景与操作 | 必须满足的通过条件 | 证据 |
|---|---|---|---|
| A01 | 新用户不填写 API Key 先体验 | 可用平台提供的合规示例物体进入训练；清楚区分示例资产与用户生成资产，不出现隐含付费调用 | 首次访问录屏、零外部调用记录 |
| A02 | 手机拍照并生成物体 | 拒绝相机可选相册；裁剪并确认主体、实际发送图片、尺寸质量预检、初估CP与费用约束；生成后才确认实际代理和精确CP。生成成功但不可参赛时说明原因并保留合规私有输出，不保证第三方退款 | 手机录屏、任务事件和报价记录 |
| A03 | 电脑导入合法 3D 文件 | 支持格式按产品规格展示；选择单位和已知尺寸后，预览与最终比赛尺度一致；无需模型调用的清洗不伪造 token 费用 | 文件样例、尺度测量、调用记录 |
| A04 | 手机对电脑完成 1v1 | 两端从准备到结算完整完成；键盘与触屏均能移动、转向和执行同等动作；最终结果、规则版本和比赛 ID 一致 | 双端录屏、权威结果 |
| A05 | 保存并在另一设备继续 | 同一账号可读已完成资产和费用记录，生成中的任务不因关页重复执行；不可读取其他账号私有资产 | 双设备记录、越权测试结果 |

## 物体与物理可信度

| 编号 | 场景与操作 | 必须满足的通过条件 |
|---|---|---|
| P01 | 同一实物分别用100mm、10cm、0.1m编码成三份等价网格 | 正确选择各自单位后边长均为0.1m、体积均为0.001m³；相同数值网格故意选错单位应出现尺寸差异并被校准识别，不把声明不同单位本身当等价 |
| P02 | 上传没有真实尺度的一张照片 | 系统明确要求用户填写至少一个已知尺寸，或保持未校准状态；未校准资产不能进入正式匹配，不将 AI 估值标为测量值 |
| P03 | 均匀实心与空心/复合物体的质量路线 | 已验证均匀实心可用ρV；空心/复合或未知V_solid用实测/声明质量加确认的代理惯量近似。来源分开显示，密度估算不覆盖实测质量；改动后生成新版本并重算预算 |
| P04 | 开放网格、零面积、非有限值、负缩放、超薄、异常长条 | 有界处理资源，非法数据拒绝或规范化；V_solid未知可用null＋确认质量＋可靠代理，不因未知实心体积一律拒绝。无法可靠构造代理或满足质量/尺寸限制才拒绝参战，修复差异须确认 |
| P05 | 从同高处落下、斜面滑动、已知冲量推动 | 固定规则下结果处于测试基准容差内；建立米、千克、秒基准；重力目标 9.81 m/s²。自由落体在首次接触前与解析值偏差目标不超过 2%，其余容差由物理原型冻结 |
| P06 | 复制物体缩放后比较 | 展示缩放引起的体积、质量、惯量和竞技预算变化；预算过限禁止准备，不能只改渲染尺寸绕过限制 |
| P07 | 手机省电档与电脑高画质档比对同一物体 | 权威碰撞体散列、质量、尺寸和驱动约束完全相同；仅视觉 LOD、分辨率、光影变化 |
| P08 | 杯子、空壳和复合材质样例 | 用户清楚看到首版支持的实体/壳体近似及不可推断项；不把包围盒体积直接等同材料体积。超出首版物理模型的资产被限制、说明或拒绝 |

物理求解器在固定版本、相同初始数据和顺序等条件下的确定性，不替代本项目的完整回放验收；初始化计算和对象添加顺序也属于验证范围。[Rapier 确定性条件](https://rapier.rs/docs/user_guides/javascript/determinism/)

## 实时对战与反作弊

初始目标：每局最多 120 秒，物理 60 Hz、快照 20 Hz、输入 30 Hz，全部待原型验证。规则版本必须冻结这些参数，发布验收不能边测边改而不记录。

| 编号 | 场景与操作 | 必须满足的通过条件 |
|---|---|---|
| M01 | 客户端上报任意位置、速度、质量或胜负 | 消息被忽略或拒绝；客户端只提交动作意图，结果只由服务器确认；两端收到相同审计事件 |
| M02 | 发送重复、乱序、未来序号、过期与畸形输入 | 输入单调序号去重；时间窗及速率限制生效；NaN、Infinity、越界轴值和超长载荷不能改变合法世界状态 |
| M03 | 键盘同时满油门/满转向与触屏对应操作比较 | 油门、转向是独立控制轴，两端都能达到(1,1)，不做单位圆归一化；总功率、牵引与能量仍受同一上限。高帧率/发送频率不增加推力 |
| M04 | 战局开始后修改物理卡、API 设置或本地时间 | 本场继续使用赛前冻结资产与规则；模型 API 不在实时仿真热路径；客户端时间不决定比赛时长 |
| M05 | RTT 100 ms、抖动 20 ms、丢包 1% | 50 场双端测试无结算分歧、无重复结算；记录输入到权威确认和画面修正分位数。操作延迟目标须在原型后冻结，并先用感知测试确认可玩 |
| M06 | RTT 150 ms、抖动 30 ms、丢包 2% | 两端能显示网络风险并继续或安全退出；无无限追赶、积压输入爆发或越界模拟。若达不到可玩标准，禁止把该网络档列入参战支持范围 |
| M07 | 断网、切后台、旋转时触摸取消 | 无新输入250ms后归零，重力惯性仍运行；每人每局累计失联15秒，重连不重置。连接断开或心跳超过2秒触发失联并回溯最后心跳；所有值赛前冻结 |
| M08 | 同步出界、出界与对手失联到期、最终tick出界、单纯时间到 | 每步先合并双方lose事件：一方lose判负、双方lose平局、都无lose才按时间到平局；出界连续计数回安全区归零。相同服务器构建与证据结果一致，两端读懂原因 |
| M09 | 服务器压力达到目标并发 | 在明确实例规格、资产最坏预算与房间数下，物理 tick 耗时 p99 目标小于 16.67 ms，连续 30 分钟无无界追赶。达到过载阈值停止接新房间，不暗中改变正在进行的物理规则 |

## 费用与用户自己的 API

| 编号 | 场景与操作 | 必须满足的通过条件 |
|---|---|---|
| C01 | 分别上传大但简单、小但复杂的物体 | 明确区分实际模型 token、供应商生成费用、平台处理费用和竞技预算；体积不被当作 API 实测 token；无调用不得显示虚构 token |
| C02 | 分别确认hard、estimate、unknown报价 | 报价列币种/计费单位、计费方、有效期、一次收费提交上限和平台硬上限；hard列可靠第三方上限，estimate逐任务显式接受可能超出估价且不得称硬上限，unknown阻止收费提交。连接测试也遵循同一授权规则 |
| C03 | 连点生成、换幂等键消费同一报价、重复回调 | 同一quote原子绑定一个operation，最多一次收费提交；不同键不重复消费，重复回调不重复结算，断网可补查；同键不同参数报冲突 |
| C04 | 供应商已接受任务，但本地请求超时 | 状态明确为“费用待核对”，保留供应商任务 ID；优先查询任务，不盲目重复创建；平台账单与外部供应商可能已产生费用分别解释 |
| C05 | 取消任务、密钥失效、配额不足、生成质量不合格 | 明确显示是否已发生外部费用、可退的平台费用、可保留的输出和下一步；不承诺外部供应商一定退款；重试须使用新报价或原报价允许范围 |
| C06 | 比赛进行时观察费用 | 正常控制、碰撞与结算不触发大模型 API；对战费用规则在入场前已展示，不能因物体碰撞次数意外产生无限费用 |

## 上传、密钥与账户隔离

| 编号 | 场景与操作 | 必须满足的通过条件 |
|---|---|---|
| S01 | 上传恶意网格、超大纹理、压缩炸弹、外链资源 | 解析在资源隔离工作进程中运行；限定文件、解压后、顶点、纹理像素、CPU 时间和内存；外链默认拒绝，无任意代码执行；失败返回可理解原因 |
| S02 | 用用户 A 查询 B 的资产、原图、模型任务、账单和回放 | 所有读取、修改、签名下载和房间加入均拒绝越权；知道 ID 不构成授权，日志记录拒绝且不泄露内容 |
| S03 | 保存和测试用户 API Key | 浏览器不使用 localStorage 持久化密钥；保存后仅返回脱敏标识；服务端加密并按账号隔离。普通日志、追踪、错误回包、分析事件和导出中均无密钥原文 |
| S04 | 自定义 endpoint 指向私网、回环、云元数据或重定向 | 默认远程接入只允许受控 HTTPS 公网目标；DNS 解析与每次重定向、任务轮询、输出下载都重新校验；测试不能访问内网和元数据服务；禁止把凭据转发到不同来源 |
| S05 | SSRF DNS 重绑定与 IPv4/IPv6 编码变体 | 解析后固定受允许目标并限制出口；地址变体均不能绕过；确需局域网自托管模型时走单独设计的本地桥接器，不能放宽公网站点的默认隔离 |
| S06 | 删除照片或整个资产 | 页面说明原文件、衍生资源、回放关联和备份的删除时限；在声明时限内撤销访问并清理；已冻结比赛记录按明确保留策略匿名化或保留必要审计信息 |
| S07 | 模型识别输出夹带指令或返回错误 JSON | 输出只作为不可信数据进入严格字段校验；不能改变服务器权限、读取密钥或绕过规则；物理参数必须经过限制与用户确认 |
| S08 | 生成中删除资产，随后收到上游成功回调 | tombstone阻止重新创建草稿、可访问预览和发布版本；迟到产物隔离后清理，已发生第三方费用独立显示 |
| S09 | 两名玩家加载对手资源，第三人尝试复用链接 | 本局参与者只读必要比赛派生资源；对手原图/原模型/密钥不可读；第三人、过期或跨局授权不能下载 |
| S10 | 带动画/骨骼/morph的GLB与多静态节点 | 动画类先要求外部烘焙，不执行；多静态节点规范化后与预览、代理、比赛姿态一致 |

## 恢复、回放和发布阻断

| 编号 | 场景与操作 | 必须满足的通过条件 |
|---|---|---|
| R01 | 观看已完成比赛并尝试审计重演 | 普通回放按权威位姿帧完整播放并显示同一终局，保存版本/散列/输入tick。审计重演另比状态哈希；不一致只标重演未复现，不否定仍可用的位姿回放，不伪造完全重现。纯输入重放承诺须另过确定性验收 |
| R02 | 比赛中杀死房间进程 | 没有已提交终局的比赛进入待核对；无法证明结果则无效局，不随机判胜、不更新竞技分；平台入场预占释放。已提交终局通过幂等恢复完成一次结算 |
| R03 | 结算提交后、用户收到通知前杀进程 | 重启后查询得到同一结果；积分、费用、奖励均只执行一次；客户端可恢复结算画面 |
| R04 | 手机内存回收或 WebGL 上下文丢失 | 有恢复说明；重新加载取权威快照并遵守普通断线规则；对手不能被客户端故障无限暂停；未确认的配置草稿按约定恢复 |
| R05 | 低档与高档真机连续游玩 | 各目标机型完成至少 20 分钟运行和冷启动测试；省电档稳态帧率目标 30 FPS、标准档 60 FPS，记录帧耗时分布与降频；未达标机型降档、优化或明确列为不支持 |
| R06 | 完成发布审查 | 无未解决 P0/P1；所有费用、权威结果、越权与密钥测试必须通过；未过真机组合不得标为已支持。其余可延后项记录负责人、影响和补救，不用总分抵消关键失败 |
| R07 | 快照在输入收到但尚未应用时发出 | lastAppliedSeq不得提前推进；实际应用后与appliedAtTick对应，客户端不会丢掉尚未应用的预测输入。重连返回序号基线且不重发旧积压输入 |

P0 表示安全、不可控支出、跨账号泄漏或破坏比赛结果可信度；P1 表示核心闭环无法完成、跨端明显不公平或关键故障无恢复。设计中的目标值只在相应实现与测试通过后才能转为产品承诺。

每次验收留存：提交或构建标识、规则版本、设备与网络条件、测试样例、结果、未解决项和复验日期。当前项目尚无运行中的产品，上述证据暂未产生。
