# 物竞场 v0.3 产品规格

状态：设计草案；实时操控和主流设备覆盖已由用户确认，其余数字为待验证的设计默认。

## Problem Statement

玩家希望让自己拍摄或制作的物体参加实时对战，并理解尺寸、质量和材质如何影响结果。现有图像转 3D 工具往往只能生成外观，缺少尺度校准、物理约束、公平预算、跨设备操控和透明的自带模型 API 接入。

## Solution

玩家在浏览器选择照片或导入文件，平台生成或整理外观，玩家确认尺寸和物理档案。校验通过后，将竞技物体固定在标准驱动底座上，在相同规则的 1v1 擂台里实时推挤对手。手机与电脑共享服务器裁判；模型只参与赛前制作，不参与胜负判断。

首发用预置物体体验完整一局，再扩展导入与照片生成。生成前先确认裁剪主体、实际发送图片、尺度/质量预检、初估 CP 与费用约束，不承诺生成后能参赛；生成后才查看实际外观、碰撞代理和精确 CP，确认后发布和参赛。

## User Stories

1. 作为新玩家，我希望无需配置 API 就能用预置物体练习，以便先判断游戏是否好玩。
2. 作为手机玩家，我希望拍摄或从相册选图，以便把身边的物体放入平台。
3. 作为建模玩家，我希望导入 GLB 或 STL，以便复用自己的作品。
4. 作为建模玩家，我希望明确文件单位与朝向，以免毫米模型被当成米。
5. 作为玩家，我希望输入一个实测长度并查看缩放结果，以便校准尺寸。
6. 作为玩家，我希望知道背面和内部是生成或假设的，以免误以为照片已还原全部结构。
7. 作为玩家，我希望选择材质或填入实测质量，以便物体有合理惯性。
8. 作为玩家，我希望看到不可确定的参数，以便补充资料或采用明确的简化假设。
9. 作为玩家，我希望查看碰撞代理，以便理解空洞、尖端和凹槽如何参与接触。
10. 作为玩家，我希望在练习区验证翻倒、碰撞和移动，以便改正装配。
11. 作为玩家，我希望调整尺寸、固定装配朝向、动力与电量，并实时看到 CP，以便在相同预算下设计。
12. 作为玩家，我希望了解每次处理的费用范围，以便决定是否继续。
13. 作为自带模型玩家，我希望接入自己的兼容 API，以便使用已有服务。
14. 作为自带模型玩家，我希望知道供应商可能已经扣费，以免平台失败时产生错误退款预期。
15. 作为玩家，我希望处理任务可重试而不重复扣平台额度，以便网络故障不造成重复消费。
16. 作为玩家，我希望切换设备后能继续编辑和查看处理进度，以便手机上传、电脑调整。
17. 作为玩家，我希望按键和触屏具有相同的最大指令能力，以便公平竞技。
18. 作为玩家，我希望看见网络状态并在短暂断线后回到原局，以便理解中断后果。
19. 作为玩家，我希望知道推台、翻倒和超时的胜负条件，以便制定策略。
20. 作为玩家，我希望设备低画质时仍使用同一套碰撞规则，以便性能不改变比赛。
21. 作为玩家，我希望赛后查看输入、状态和规则版本对应的回放，以便理解输赢。
22. 作为玩家，我希望排位中不能偷偷更改质量、碰撞体或电机功率，以便信任对手。
23. 作为玩家，我希望撤销 API 密钥并删除私人资产，以便控制自己的资料。
24. 作为平台运营者，我希望隔离危险文件、限制算力并识别无效局，以便稳定提供服务。
25. 作为低性能设备用户，我希望进入前得到能力检测和明确的替代入口，以免支付后才发现不能玩。
26. 作为玩家，我希望看到供应商将接收哪些图像，以便决定是否发送个人资料。

## Implementation Decisions

- 六个边界：资产处理、物理档案、模型代理、费用账本、比赛房间、客户端。生成任务和比赛房间独立，生成故障不影响已就绪物体对战。
- 采用 Three.js 可视化、Rapier 服务器权威物理、Colyseus 房间；具体依赖版本在实现前通过兼容性试验锁定。
- 浏览器 WebGL2 为比赛渲染基线；WebGPU 可选。触屏和键盘都映射为相同的归一化油门、转向、刹车。
- 照片不能证明真实密度与隐藏结构。尺度必须人工确认；非封闭模型没有自动实心体积推断通道，按确认的质量与代理形状估算惯量，并标注近似。
- 竞技物体发布后不可变，匹配时冻结双方资产版本、物理档案、CP 公式、地图和规则哈希。
- 对战采用刚体推台，不模拟碎裂、热力、流体或真实伤害。物体作为底座载荷，遵守接触牵引和能量限制。
- 报价、实际模型用量、平台处理额度和参赛 CP 分开；BYOK 不默认代扣第三方费用。
- 首发允许预置资产免 API 使用；照片路线必须先经适配器能力检测、报价及用户发起处理。

## Testing Decisions

主要验收边界是一条用户可见的完整闭环：两个设备选定冻结资产、进入同一房间、操控、收到同一个结算与可解释回放。资产、费用和 API 是跨越独立故障边界的补充合同测试；只断言外部行为，不测试私有函数组织。

当前无既有实现和测试可借用。首个任务建立上述闭环和确定的对局记录；后续分别证明单位错误被拦截、超额生成不启动、重试不重复扣款、伪造位姿不生效、模型失败不阻断已有资产、服务器崩溃不虚构胜负。真机与弱网测试详见验收清单，所有性能阈值均为目标而非实测。

## Out of Scope

首发不包含任意机械关节编辑、自由武器、软体与碎裂、工程级材料认证、无限尺寸、自训练大模型、主机商店发行、智能电视或手表完整操控、交易市场、充值支付或奖金系统。原生客户端、FBX/OBJ/STEP/BLEND 转换、多图扫描与排位开放均需后续验证。

## Further Notes

用户已授权先生成项目文件、研究并模拟用户质询；模拟质询不替代真人测试。推荐先做 1v1 推台和私密房间，等跨设备手感、物理与成本门槛通过后再开放排位。具体实现顺序见本地任务。
